## Algorithms and Data Structures

### Animal Shelter Dashboard

The Animal Shelter Dashboard demonstrates my ability to work with algorithms, data processing, filtering, sorting, and data presentation.

**[View Original Artifact](LINK-HERE)**  
**[View Enhanced Artifact](LINK-HERE)**

### Artifact Narrative

The artifact I selected for this enhancement is the Animal Shelter Dashboard, which I originally developed in CS-340: Advanced Programming Concepts. The application was created in 2026 using Python, MongoDB, Dash, and Plotly to provide an interactive dashboard for managing and visualizing animal shelter records. The original project connected to a MongoDB database through a custom CRUD module and allowed users to view animal records, apply basic rescue-type filters, and display visualizations using charts and an interactive map.
Justification for Inclusion

I selected this artifact because it demonstrates my ability to apply algorithms and data structures to improve the efficiency and usability of an existing application. While the original dashboard successfully displayed and filtered animal shelter data, its search capabilities were limited to predefined rescue categories. I realized I could improve how users interact with large datasets by implementing more advanced searching, filtering, and sorting.

For this enhancement, I designed and implemented a filtering algorithm that allows users to search animal records using multiple criteria, including breed, age range, outcome type, rescue category, and keyword searches. The keyword search examines multiple fields, including the animal's name, breed, identification number, and outcome type, providing a more flexible method of locating records. I also implemented dynamic sorting that allows users to organize records by name, breed, age, or outcome date in either ascending or descending order.

The enhancement also improved how data is organized before being displayed. MongoDB documents are retrieved and stored within a Pandas DataFrame, where filtering and sorting algorithms are applied before the updated results are presented in the dashboard. These processed results are then used to update the interactive data table, breed distribution chart, and map visualization. This artifact demonstrates my understanding of searching algorithms, conditional logic, data organization, and the use of appropriate data structures to improve application performance and user experience.

Course Outcomes

This enhancement successfully met the course outcomes that I identified during Module One. It supports Course Outcome One by improving the way users retrieve and analyze organizational data, making animal shelter records easier to search and interpret. 
It supports Course Outcome Two through the documentation and explanation of the enhancement process within my code review, narrative, and ePortfolio.
Most directly, the enhancement fulfills Course Outcome Three by applying algorithmic principles to design a more effective computing solution. The implementation of multi-criteria searching, dynamic filtering, sorting algorithms, and data processing demonstrates my ability to evaluate and improve an existing software application using algorithmic techniques. 

Finally, the project supports Course Outcome Four through the use of modern computing tools and technologies, including Python, MongoDB, Dash, Pandas, Plotly, and interactive mapping components, to create a more functional and user-friendly dashboard. Because the enhancement fully addressed the objectives established in Module One, no changes to my original outcome coverage plan were necessary.

Reflection

Enhancing this artifact provided valuable experience in designing algorithms that improve both application functionality and the overall user experience. Throughout the project, I learned that organizing data effectively is just as important as retrieving it from the database. I developed a workflow that processes records within a DataFrame before presenting them to the user. This reinforced the importance of selecting appropriate data structures that support efficient searching, filtering, and sorting operations.
One of the greatest challenges involved adapting the original project to run in my local development environment after it had originally been developed in a different environment. This required configuring MongoDB locally, importing the animal shelter dataset, updating the database connection, and resolving compatibility issues related to newer versions of Dash and Jupyter. I also encountered challenges handling inconsistent data types when implementing dynamic sorting, which required additional data cleaning and validation to ensure the application could sort numeric, text, and date fields correctly.

Overall, this enhancement strengthened my understanding of algorithms, data structures, and data processing within real-world applications. It also reinforced the importance of debugging, testing, and iterative development when improving existing software. The finished dashboard is significantly more flexible and user-friendly than the original version, demonstrating not only stronger technical skills but also my ability to evaluate an existing solution and implement meaningful improvements that enhance the user's ability to analyze and interact with data.

## Databases

### Weight Tracker Android Application

The Weight Tracker Android application demonstrates my ability to integrate database functionality and persistent data storage into a mobile application.

**[View Original Artifact](LINK-HERE)**  
**[View Enhanced Artifact](LINK-HERE)**

### Artifact Narrative

For this enhancement, I used my Weight Tracker Android app from CS 360 Mobile Architecture and Programming (Feb 2026). The app was originally created as a mobile app where users could create an account, log in, and track their weight over time. It uses a SQLite database to store information and displays weight entries in the app. I chose this project because it already had a database component, so it gave me a good starting point for showing how I could improve the way data is stored, retrieved, and used.

Why I Selected This Artifact

I included this artifact in my ePortfolio because I think it shows a lot of different software development skills at once. The app includes a user interface, login functionality, a SQLite database, and CRUD operations that allow users to add, view, edit, and delete weight entries. For the enhancement, I expanded the database functionality so that weight information is connected to the logged-in user instead of treating all weight records as one shared set of data. I also added the ability to set and save a goal weight and added a progress summary that uses the stored data to show things like starting weight, current weight, total change, and progress toward the user's goal. These changes made the database more useful to the actual functionality of the application instead of simply using it as storage like people might use Excel.

Course Outcomes

Course Outcome 1: Support organizational decision-making in the field of computer science through the use of well-designed computing solutions.
I met this outcome by enhancing the Weight Tracker so that the data stored in the database is actually useful for making decisions. Instead of only saving individual weight entries, the application now uses the stored data to calculate the user's starting weight, current weight, total weight change, and progress toward a saved goal weight. This turns the database information into a useful progress summary that could help a user make decisions based on their weight history.

Course Outcome 2: Design, develop, and deliver professional-quality oral, written, and visual communications.

I met this outcome through the way I documented and presented the enhancement. I explained the original database design, the changes I planned to make, and the results of those changes through my code review, enhancement narrative, and ePortfolio. I also took screenshots showing the application working, including the login process, adding and editing weight entries, setting a goal, and displaying the updated progress summary. This helped me communicate not only what I changed in the code, but also show that the enhancement actually works.

Course Outcome 3: Design and evaluate computing solutions that solve a given problem using algorithmic principles and computer science practices and standards.

This enhancement met this outcome because I redesigned how the application stores, retrieves, and uses its data. One major improvement was connecting weight records to a specific logged-in user instead of having one shared collection of weight entries. I also added goal-weight storage and calculations that use the user's saved records to generate their progress summary. I tested the application afterward to make sure adding, editing, deleting, and retrieving records still worked correctly with the new design.

Course Outcome 4: Demonstrate an ability to use well-founded and innovative techniques, skills, and tools in computing practices.

I demonstrated this outcome by working with several technologies together, including Android development, Java, Kotlin, SQLite, and CRUD operations. I modified the SQLite database structure and DBHelper methods and then updated the rest of the application so that it could work correctly with those changes. I also built and tested the finished application in Android Studio using an Android emulator. This gave me more experience working with the different layers of a real application rather than making an isolated code change.

Course Outcome 5: Develop a security mindset that anticipates vulnerabilities and protects data and resources.

I addressed this outcome by improving how user data is separated and validated. Weight entries are now associated with the logged-in user's ID, which helps prevent one user's records from being mixed with another user's information. The application also validates required input and numeric weight values before saving them to SQLite. While this is still a student application and could be made more secure—for example, the login system could eventually use password hashing instead of storing passwords directly—the enhancement gave me a better understanding of how database design, validation, and user-specific access all contribute to protecting data.

Reflection on the Enhancement Process

This enhancement definitely taught me more than I expected about how connected everything is in an application. A change to the database affected the methods in DBHelper, but then those changes also had to be reflected in MainActivity and the way the logged-in user was passed through the application. I learned that improving a database is not just about adding another table or column. You also have to think about how the application creates, reads, updates, and deletes that information and how the user actually interacts with it.

I did run into a few challenges along the way. One of the biggest was updating the existing code after changing the database methods because some of the older method calls no longer matched the new parameters. I also had some setup issues getting the Android project to build because the Android SDK path was not initially configured correctly. After working through those problems, I was able to get the project to build successfully and run it in the Android emulator. I tested creating an account, logging in, adding multiple weight entries, editing and deleting entries, setting a goal weight, and viewing the updated progress summary. Seeing all of those pieces working together made the enhancement feel much more complete and helped me understand how database design directly affects the rest of an application.
